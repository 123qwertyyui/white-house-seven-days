# 古巴导弹危机：三方决策室

美国12个、苏联10个、古巴10个决策，分别覆盖四章：危机前背景、危机公开、交换与执行、1963年后续议题。纯静态页面，不接入AI服务，不需要API密钥。

## 运行

普通HTTP服务或GitHub Pages打开index.html。入口依次加载us-core.js、content.js、model.js、analysis.js、app.js与style.css。无构建依赖、无外部字体脚本、无接口请求。build-us-core.cjs仅用于从先前剧本生成美方基础数据，不是运行依赖。

每个角色独立保存于cuba-three-perspectives-v1。切换角色不会合并三个世界或让一份存档操纵另一份。当前角色控制本国行动，其他两方按明确情境规则回应。这是单人、多角色视角的规则模拟，不是同步多人对战或真正运行大语言模型的智能体。

## 信息、权限与结果

- 每项决定前回顾上一选择与回应，再单独给出新发生的事件。外生历史节点不被写成上一选择必然造成的后果。
- 美国、苏联、古巴各自有单独时间线、知识范围与可修改字段。古巴决策阶段不展示美苏关于土耳其导弹的私下细节；复盘才补充相关档案。
- 苏方控制本国核武器使用。古巴的附条件建议不被转换成自动核发射命令。
- 美苏原则交换不等于武器已撤除；古巴许可不等于其他方接受全部条款或检查已经完成。
- 未部署核导弹和军事攻击选项会在明确边界结束分支，不把反事实路线强行写回真实历史。未达成撤除的路线进入1963年时标注为假设议题。

## 复盘

先解释整条路线，再指出政策间的衔接和张力。每段机制解释附实际选择证据。每项历史对照包含玩家选择、史实、方向差异、具体理论解释和可点击原始来源。无历史准确率、国家总分或核战概率。

安全困境、信息不对称、条件交换、承诺履约、联盟政治、升级控制、双层博弈与制度合作按相应节点使用。理论不能替代史料，也不证明真实国家只有一个目标或没有进攻意图。

简化规则：美方提出与撤除核实相联系的不入侵保证及相应调整措施后，苏方在美方路线中原则接受；苏方提出附条件撤除后，美方在苏方路线中愿意讨论保证；坚持公开土耳其交换则保留公开前提分歧。美苏不能替古巴批准现场检查。古方可在自己的路线中原则允许受限核查，仍需对方确认与实际执行。通信和禁试不替英国、美国参议院或执行人员完成程序。

复盘用只替换一步、保持其他已作出选择不变的重跑检查规则内差异。原分支提前结束后，不编造未作出的未来决定。这不是对真实历史的因果识别或均衡估计。
