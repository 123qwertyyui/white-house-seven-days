# 古巴导弹危机：整局策略复盘

本版保留八章历史情境，重做分析。终局不再展示GMCR稳定性、MID等级、状态编码或国家总分。原有求解器不再作为网页运行依赖。

## 解释方法

采用有边界的案例分析和按理论编码的选择记录。证据来自本局实际选项；安全困境解释军事保护措施为何也可能威胁对方，条件交换解释单方撤除为何需要对方承诺。每个解释段落附上对应章节的实际决定，不推断玩家人格，也不替玩家编造改变主意的动机。

程序只保留一项数值型规则：美国是否提出完整条件交换，0为未提出，1为提出。“完整交换”在此指不入侵保证，以及苏联按约撤除、安排核实后美方相应调整海上措施。没有进入攻击分支且提出这套安排时，本作将苏方答复设为原则接受。这是明确的情境假设，不是估计的历史决策函数，不是博弈均衡或核战概率。

核实办法按现场要求、替代办法和程序磋商分别记录，不相加、不排序成高低分。古巴不会因美国请求调停就自动同意核查；核实选择不会暗中替美国新增不入侵保证。

## 复盘如何形成

- 区分早期交换、后期补充交换、始终未补齐条件、早期攻击和后期报复等路线。
- 连起前期压力、承诺变化、突发事件应对和古巴准入，说明相互关系。
- 识别具体张力，例如现场授权与白宫克制，而不把合法的路线调整直接判为矛盾。
- 只替换一次选择，保持其余已作出的选择不变重新运行。若后来的决定补齐条件，则明确说明终局可能相同而过程不同。若原局已在军事分支结束，则不编造未作出的后续选择。

这项比较验证的是本作规则内部的差异，不是对真实历史的因果识别。军事能力、决策者意图、土耳其政府和现场部队均没有被完整模拟。安全困境不能把真实的进攻或威胁一概解释成误会。第5章的侦察机击落事件按史实设置，不能归因于玩家某项海军授权。

## 文件与存档

入口加载`bargaining-v3.js`、`scenario-v3.js`、`review-v3.js`、`review-ui-v3.js`和`app-v3.js`。无AI调用、无接口密钥。新存档键`cuban-crisis-strategy-v3`，可以从第二版的实际选择重建进度。旧模型输出与伪造状态一律不作为复盘依据。完成前锁定复盘，重选后重新锁定。

`node test-v3.cjs`覆盖全部2973条可结束选择序列、恢复重建、证据引用、条件交换的时序、单步比较、军事分支边界与旧存档迁移。浏览器检查另覆盖完整流程、结束前锁定、手机、下载与旧存档直接生成新复盘。
